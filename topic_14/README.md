# ДЗ по теме 14. Kubernetes: ресурсы. Вариант 1

**Дисциплина:** DataOps. **Тема:** k8s ресурсы. **Вариант:** 1

## Цель

Определить требуемые ресурсы кластера Kubernetes для приложения: БД, кеш, бекенд, фронтенд. Рассчитать с запасом 10% и разделением на master/worker.

## Исходные данные (вариант 1)

- **БД (StatefulSet):** 3 реплики — 4 ГБ RAM, 1 CPU на реплику
- **Кеш (StatefulSet):** 3 реплики — 4 ГБ RAM, 1 CPU на реплику
- **Бекенд (Deployment):** 10 реплик — 600 МБ RAM, 1 CPU на реплику
- **Фронтенд (Deployment):** 5 реплик — 50 МБ RAM, 0,2 CPU на реплику
- **Запас:** 10%
- **Master:** мин. 3 ноды, 4 ГБ RAM + 2 CPU на ноду

## Расчёт

**Суммарно приложение:**

- RAM: 3×4 + 3×4 + 10×0,6 + 5×0,05 = **30,25 ГБ**
- CPU: 3×1 + 3×1 + 10×1 + 5×0,2 = **17 ядер**

**С запасом 10%:** ≈34 ГБ RAM, ≈19 CPU.

## Архитектура кластера

- **Master:** 3 ноды × (4 ГБ, 2 CPU) = 12 ГБ, 6 CPU
- **Worker stateful (БД + кеш):** 2 ноды × (16 ГБ, 4 CPU) = 32 ГБ, 8 CPU
- **Worker stateless (бекенд + фронт):** 2 ноды × (8 ГБ, 6 CPU) = 16 ГБ, 12 CPU
- **Итого:** 7 нод, 60 ГБ RAM, 26 CPU

## Структура решения

- `calc_resources.py` — скрипт расчёта ресурсов (запуск: `python3 calc_resources.py`)
- `manifests/` — примеры манифестов K8s (backend-deployment.yaml и др.)

## Выводы

Для варианта 1 с запасом 10% требуется около 34 ГБ RAM и 19 CPU по приложению. Кластер из 3 master и 4 worker покрывает нагрузку с запасом.
